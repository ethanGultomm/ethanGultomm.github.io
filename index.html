What it does

  • Register and log in with email and password
  • Add, list, update, and delete job applications
  • Find an application by ID or by position
  • Every application belongs to a user

Design notes

  • Stateless auth: login returns a JWT that expires after 7 days, sent as a bearer token
  • Passwords are hashed before they’re stored
  • Prisma gives a typed data layer over PostgreSQL
  • Routes and middleware live in separate modules

Example request

POST /applications
Authorization: Bearer <token>
Content-Type: application/json

{
  "company": "Amanda Corp",
  "position": "Backend Engineer",
  "status": "applied"
}

ModelFields

Applicationid, company, position, status, date added, userId

Physics EngineWork in progress

What works today

  • Circles that fall under gravity
  • A container the circles collide with and bounce off
  • Floor friction and energy loss on every bounce
  • A fixed 60 Hz simulation timestep
  • Circles spawned from the center in a rotating radial pattern

What’s next

  • Circle-to-circle collision detection and response
  • One shared shader and mesh for all circles, so it scales to many bodies
  • Shader compile and link error checking

How it works

  • Simulation and rendering are separate: a World owns a list of rigid bodies, each with a position, velocity, mass, restitution, and a polymorphic Shape that knows how to draw itself.
  • Each step applies gravity to the velocity, then moves the body by its velocity (semi-implicit Euler integration).
  • Wall collisions push the circle back inside the container and reflect its velocity, scaled by a restitution of 0.7 so every bounce loses energy.
  • Each circle is drawn as a 50-segment triangle fan, with an orthographic projection that keeps circles round when the window is resized.
  • OpenGL resources are released in the Circle destructor (RAII), so bodies clean up after themselves.
  • Built with CMake and Ninja, with GLFW and GLM installed through a vcpkg manifest.
